# Port: Canon components to Glimmer

Source: `~/GitRepos/delphitools-ios/delphitools/delphitools/Core/Canon/*.swift` at commit `4628b8d`.
Read it with `git -C ~/GitRepos/delphitools-ios show 4628b8d:<path>`; the working tree of that repo is off limits for edits (a parallel session refactors `Core/Canon`).
Reference for behaviour: `CANON.md` and `Features/Debug/CanonGalleryViewController.swift` in the same repo, same commit.
Reference for web conventions: `~/GitRepos/delphitools` (Ember 7.1, `.gts`, Vite) and its `DESIGN.md`.

## Decisions

| Topic | Decision |
|---|---|
| Package | `delphicanon`, an Ember v2 addon (current `@ember/addon-blueprint`), TypeScript, `.gts` strict mode, Glint. A demo app in the same repo holds the gallery. |
| Names | One Swift class, one component, same name: `CanonButton` in `src/components/canon-button.gts`. Helpers and pure logic in `src/lib/`. Modifiers in `src/modifiers/`. |
| Styling | Plain CSS, one co-located file per component, imported by the component. Tokens as `--canon-*` custom properties in `src/styles/tokens.css`, values from the iOS asset catalog (`delphi*.colorset`). Dark mode under both `prefers-color-scheme: dark` and `html.dark`, matching the web app. No crayon, no SCSS. |
| Units | 1 pt = 1 CSS px. Rows 52, flush controls 44, primary button 68, secondary 60. |
| API | UIKit properties become args; `.valueChanged` / closures become `@onChange` style callback args; internal state is `@tracked`. Section lists become named blocks (`<:sidebar>`, `<:main>`, `<:banner>`, `<:footer>`). |
| Layout | Size classes become container queries on the component, never viewport width or UA sniffing. The Duo crease becomes `@media (horizontal-viewport-segments: 2)` / `env(viewport-segment-*)`, the laptop pose `device-posture: folded` (Chromium only, progressive). |
| Platform swaps | Metal becomes WebGL2 with the same maths. `UIColorPickerViewController` becomes `<input type=color>`. The system menu becomes a native `<select>`. Photos and Files become `<input type=file>`, drag and drop, paste. Sheets become `<dialog>` or the popover API. Gesture recognisers become modifiers on pointer events with `touch-action`. |
| Dropped | Haptics. `CanonSelfCheck`. UIKit extensions on `UILabel`, `UIColor`, `UIResponder`. Mac-only components listed in CANON.md. |
| Copy | Clipboard through `navigator.clipboard.writeText`, confirmed by `CanonToast` (a service plus one outlet component, ARIA live region). |
| Privacy | No network calls in any component. No new runtime dependency without a line in this file saying why. |
| Tests | One QUnit rendering test per component. Unit tests for pure logic (maths parser and typesetter, glyph row layout, colour conversion). |
| Git | Local repo, no remote. Each parallel agent works in `~/GitRepos/delphicanon-wt/<group>` on branch `port/<group>`; the coordinator merges into `main`. |
| Registry | `registry/` builds shadcn registries for the React, Vue and Svelte ports with each CLI's own build command. One item per component (`canon-<name>`, its CSS included), `canon-tokens`, one `canon-lib-<name>` per lib file (a root `lib/` subdirectory is one item), and `canon-all`. Files install under `<components alias>/canon/`, imports rewritten to relative paths without `.ts`/`.tsx`. |
| Showcase | `showcase/` is a second Ember app in the root package, built like `demo-app/` with the root Vite, Embroider and Babel setup and its own `showcase/vite.config.mjs` (`bun run showcase`, `bun run build:showcase`). It imports `#src/components/canon-<name>.gts` and the demo's `Icon` and `GalleryArt`, copying nothing. One tile per component (61), each a framed CanonRows with a CanonHeading, a live instance in the Ember gallery's markup (the arrangements of the earlier React showcase), and the install line for the framework picked in the header's CanonSegmented. Ember is the first and default segment: it has no shadcn registry, so its lines are `npm install delphicanon` and `import CanonSlider from 'delphicanon/components/canon-slider';`; React, Vue and Svelte show the shadcn CLI command with the item URL. The lines are CanonValueLines, so a tap copies through the canon-toast service and shows the CanonToast; CanonCodeBlock confirms in place without the toast, so it is only a tile. The registry base is `CANON_REGISTRY_URL` at build time (Vite `envPrefix`), the same variable the registry build reads (default `http://localhost:4330`). `base: './'`, fonts bundled from `showcase.css` and `location = 'none'` let `dist/` sit beside the registry's `r/` in any directory. The config sets `build.rolldownOptions.input`, because `@embroider/vite` otherwise adds the root package's `tests/index.html` to a dev server rooted in `showcase/`. |

## Phase A changes to the decisions

| Topic | Change | Why |
|---|---|---|
| Row stacking | CanonRow uses a wrapping flex line, not a container query. The label grows 999 times faster than the control, so a side-by-side control keeps its width and a wrapped one fills its line. A bar or slider is the exception: it shrinks from its width down to `--canon-row-shrink-basis` (64 px) before the row stacks, so it stays beside the title. `sizingTitle` is a hidden copy of the longest title inside the label. | The break point is the label's width plus the control's width, which a container query cannot know. Ruby: a bar should not drop under its title. |
| Text sizes | `--canon-text-*` tokens are the iOS text styles scaled down (body 15, subheadline 13, footnote 12, caption 11). Geometry stays 1 pt = 1 px. | iA Writer Quattro is about a third wider than SF Condensed; at the iOS sizes segment titles truncated at the 340 px sidebar. |
| Press motion | `lib/motion.ts` and the `canon-press` modifier exist from phase A with the press tilt, spring and constants. The display group adds the pan modifiers to the same file. | Every button presses; CanonButton needed it. |
| Grid measuring | CanonGrid places spans and drops titles to symbols with a small modifier (MutationObserver, ResizeObserver, canvas `measureText`). | Balanced rows and "any title does not fit" depend on the cell count and text widths. |
| Copy | `canonCopy` is the service method `copy(text)`; it shows the toast only after `navigator.clipboard.writeText` resolves. Tests replace `service.write`. | A toast after a failed write would say Copied when nothing was copied. |
| Pattern | The consumer sets `--canon-pattern` (from `canonPatternTile(svg)`) on an ancestor, standing in for the `CanonPatternSymbol` trait. Canvases draw it as a mask in the foreground colour at 4 %. | A mask follows the theme; a baked image would not. |
| Not ported | `CanonActionBar` alias (use CanonGrid), `CanonPaddedSection` (a CSS rule in `canon-page.css`), `setCanonSectionHidden` (render conditionally), status bar bleed under a page (web pages start below the app's own header), menu-as-primary-action press handling (goes with CanonMenuCell). | No web counterpart, or it belongs to a later group. |
| Demo only | `lucide-static` (gallery icons) and `puppeteer-core` (`bun run shot`) are devDependencies, not runtime ones. | The gallery needs symbols; the addon takes icons as components. Screenshots check the gallery headlessly. |
| Readout text | CanonTimecode takes `seconds` or `text` (the `show(text:)` path) as args; FluoWrite is `--canon-segment-font`, the consumer supplies the `@font-face` (the demo loads the iOS .otf from `public/fonts`). | Args replace the imperative `show`; the addon ships no fonts. |
| Lamp blink | CanonLamps takes `flashes`, a count per lamp; a change blinks that lamp for 0.12 s. CanonReadoutBand passes `transport.loops`. | `flash(_:)` is imperative; a counter keeps it arg-driven. |
| Page strip | Pages are args; `onMove` reports a move and the consumer reorders `pages`. Pictures are URLs, placed and turned in CSS. The long-press menu is a popover opened by `contextmenu` or a 500 ms touch press; `menu` returns `{ title, action, destructive }` items. Reorder by keyboard: Alt and the arrow keys. | No UICollectionView or UIMenu; a native `<select>` cannot hold per-page actions. |
| Canvas top inset | `canvasTopInset` (CanonCanvasContent) is not ported for CanonPageStrip or CanonGlyphFlow. | Follows the phase A status bar decision. |
| Glyph flow | Glyphs are absolutely placed elements painted by the default block (`glyph`, index or null for a fading glyph); the slide, grow and fade run on the Web Animations API with the iOS curves. Removed glyphs render once more as fading ghosts. `<:empty>` stands for `paintEmpty`. | No CGContext drawing. |
| Copy in code block and text output | CanonCodeBlock and CanonTextOutput write through `canon-toast`'s `write` and confirm in place (check icon, Copied flash), without the toast, as on iOS. Share uses `navigator.share` (a file where `canShare` allows, else text) and downloads the file where there is no share sheet. | iOS confirms these two in place, not with CanonToast. |
| Middle truncation | Tile values and page names truncate at the end. | CSS has no middle truncation. |
| Solid args | `setPoint(_:animated:)` is a change of `@point` with `@animated`; `setVision(_:animated:)` is `@vision` (rows), which eases on every change after the first render. `colour` is not an arg: `colourAt(space, point)` and `pointFor(space, colour)` convert. `yaw` and `pitch` are not args. There is no `onPick`: the Swift sends only `.valueChanged`, which is `@onChange(point, colour)`. `@closestName` stands in for `ColourNames.closest` in the value read out. | Args are data; the colour name set stays out of the addon. |
| Solid space change | A new `@space` with an unchanged `@point` converts the pick, as the Swift setter does, and reports it through `@onChange`. | The parent owns the point and would otherwise hold it in the old space's units. |
| Solid input | `touch-action: none` covers the whole solid, so a touch that starts off the solid does not scroll the page (CanonGrabPan let it). Arrow keys turn the solid (not in ortho with a slice, where drags pick); the pick is read from a polite live `<output>`. Axis letters behind the camera hide instead of keeping their last place. The WebGL context keeps its drawing buffer so tests read pixels. | Web input and assistive technology; the task asked for `touch-action: none`. |
| Math: drawing | Typeset atoms draw as SVG (`text`, `rect`, `path`) in one `<svg>` per view, not as positioned HTML boxes. A static view scales down through its viewBox; a morphing view places atoms in pixels and animates each element's `transform` and `opacity` with the Web Animations API. | SVG text sits exactly on its baseline, and radicals, drawn brackets, floor corners and dashed holes are paths, as in `CanonMath.draw`. |
| Math: metrics | The typesetter takes a `Metrics` object; the components pass canvas `measureText` in `--canon-math-font` (ui-serif, New York, Iowan Old Style, Georgia). Tests pass fixed metrics. | Keeps the layout pure and testable. Chrome does not expose New York, so it sets in Iowan Old Style there; Safari with ui-serif is unverified. |
| Math: files | CanonMathGlyphs is `canon-math-view` with `@box` and `@mono`. CanonMathSubmenu is part of `canon-math-keypad`. The sheet is `canon-math-input`, a `<dialog>` the field renders. `CanonMathKeypad.cell(_:)` is `canon-math-key` with `@key`. | One component per visible part; the glyph view and the submenu have no use on their own. |
| Math: sheet | Docks to the field's CanonPage (560 px at most) when the field's CanonSplit, or the document, is at least 640 px wide; a bottom sheet otherwise, with a large height after a drag up. Short keys and editor when the window is under 800 px tall. Not kept clear of a crease. | A top-layer dialog cannot use a container query; the split's own width stands in for the size class, the window height for the host view's. |
| Math: paging | Pages are a scroll-snap strip, so a swipe is the browser's own; a tab click glides with the iOS spring (0.46 s, 0.84) in `requestAnimationFrame`. Labels drift and fade through CSS custom properties set from the scroll position. | Native swiping on touch and trackpads. |
| Math: API | Insert keys reach a field through a `CanonMathFieldHandle` passed to both (`handle.edit([key])` for `field.edit(then:)`). The field keeps its last edit until the owner passes a different `@text`. | Glimmer has no view reference to call a method on. |
| Math: keyboard | In the sheet, digits, letters, `+ - * / ^ = , . ! ( ) \|`, arrows and Backspace type as their keys; Enter is Done, Escape closes. | Desktop input; iOS had none. |
| Math: not ported | The debug launch arguments (`-mathkeys` script player, `-mathshort`, `-mathlarge`) and haptics. nCr and nPr still go out and come back as factorials, as on iOS. | Debug only; no web counterpart. |
| Unverified | The crease (`horizontal-viewport-segments`) and laptop (`device-posture: folded`) rules have no test and were not seen on a device. | No dual-screen browser available. |
| Colour state | CanonColourControls takes one `@state`, a `CanonColourSolidState` (exported from `canon-colour-controls.gts`) holding `space`, `point`, `animated`, `activeRow`, `slices`, `viewPlane`, `showsWhole`, with getters `colour`, `sliceAxis`, `isOrtho` and a `pick(point)` callback. The consumer passes `space`, `point`, `animated`, `sliceAxis`, `isOrtho` and `showsWhole` to canon-colour-solid and `pick` as its `@onChange`. A new space changes only `state.space`; the solid converts the point and reports it through `pick`. `cutsAway`, `marks` and `vision` stay with the consumer, as the Swift controls never set them. | The Swift controls held the solid and set its properties, and `solid.space` converted the point; a Glimmer component cannot set another's args. |
| Colour spaces | One Space table, `lib/colour-space.ts` (`SolidSpace`, `solidSpaces`, `spaceNames`, `channels`, `isCartesian`, `colourAt`, `pointFor`, `convertPoint`, reaches), on the conversions in `lib/colour.ts`. The solid keeps only its shader numbers and radii (`lib/colour-solid/solid.ts`). One `Rgb`, the tuple from `lib/colour.ts`, for the solid too. | The colour and solid groups each wrote a copy in parallel. |
| Colour formats | The app's primary and secondary colour format settings are args (`format`, `primaryFormat`, `secondaryFormat`), default hex and rgb. Nearest name is `nameOf(hex)`. | The addon has no settings store and no name dataset. |
| Colour not ported | `CanonColourStrip.placed(under:)` (the consumer stacks picture and strip in one CanonCanvas); CanonCopyFeedback (the `canon-toast` service's `copy` covers it). | Safe area and page fade have no web counterpart. |
| Controls: menu | CanonMenuCell is a styled cell with a native `<select>` laid invisibly over it; it has no press tilt. CanonFromTo reports `@onFromChange` and `@onToChange`. | The native picker takes the pointer, so a release would not arrive. |
| Controls: files | CanonFileCell and CanonDropZone take `@accept` and hand over `File` objects, no Photos and no temporary copies. `onImages` gets `ImageBitmap`s (EXIF orientation applied) and the file stems as a second argument, empty after a paste; Paste reads `navigator.clipboard.read()`, and a paste event inside the zone imports too. CanonFileCell has no `clear()`: re-render it. | Web file access; `imageNames` as state has no use once the names travel with the images. |
| Controls: loader | CanonLoader is the web nds-loader's CSS keyframes, not a timer; its colour is the CSS `color`. | Same table of steps, no JavaScript. |
| Controls: fields | CanonDecimalField's `show(value, range)` is `@value`, `@min`, `@max`, default 0 to no bound (no lower bound when signed). The stepper has no `insets` argument. Number and decimal fields step with the arrow keys too. Composite controls take `@labelledBy` or `@label` for their field. | Args instead of a method; keyboard access. |
| Controls: slider | CanonSlider's `@onChange` gets `(value, dragging)`, standing in for `isDragging`; it has no touch-down event, so CanonColourControls listens for `pointerdown` on it to pick the row and show the whole solid. | Args and callbacks instead of UIControl events. |
| Controls: figure | CanonFigure rolls changed characters, compared from the end, with the Web Animations API; no minimum scale factor and no Dynamic Type scaling. | No numeric text transition on the web. |
| Controls: switch grid | `CanonGrid.switches` is not a component: a CanonGrid of CanonRows with `@sizingTitle` and a CanonSwitch each, as in the controls gallery. | CanonGrid and CanonRow cover it. |
| Controls: unverified | CanonSwitch uses the 51 x 31 UISwitch geometry; the iOS 26 switch is wider and was not compared. | No simulator in this pass. |
| Colour page | The demo's `?page=colour` is CanonColourGalleryViewController: the solid over its strip is the canvas of a `halves` sidebar (`collapsesTo` 240 in one column, `pictureMeetsCrease` from `?colourCrease`); the main pane holds the controls with View, Strip palette and Deuteranopia, the cards, the value lines and their layouts, the notation input, loupe and detent wheel, and the palettes. `?colourSpace`, `?colourRow`, `?colourView` stand for the iOS launch arguments. CanonColourControls yields its block between the sliders and View plane, where the page puts View. The wells stay on the main page. | The four-matrix vision picker of the solid group is the one Deuteranopia switch, as on iOS. |
| Phase C source | Phase C ports `da09fa2` (relative to `4628b8d`). | The iOS change that added these components. |
| Notation input | The eyedropper is the EyeDropper API, left out where the browser has none (Safari, Firefox), so there is no system picker and no `pickerColour`. `show(_:)` and `show(text:)` are `@colour` and `@text`; `commit()` is Return and leaving the field. Typed text holds until the shown value changes. | The task asked for the EyeDropper API; it takes no starting colour. |
| Detent wheel | No haptic tick or clack: the tick is `@onSelect`, once per row crossed. Rows are the default block, given index and focus; `CanonDetentWheelRow` is the gallery's centred label, not a protocol. `reload(spin:)`, `reconfigure()` and the DEBUG `fling` are not ported: a new `@count` snaps to `@selected`, rows re-render. Role slider; Down and Right go to the next row, Up and Left to the one before, Home and End to the ends. The mouse wheel turns it by `deltaY` over the row height and the nearest row catches it 120 ms after the last event. | Haptics are dropped; web input and assistive technology. |
| Loupe | `show(_:colour:)` is `@pixels` (ImageData, ImageBitmap, canvas or image) and `@colour`. The canvas is the pixels' own size, scaled up by `image-rendering: pixelated`. The consumer places it with `frame` from `lib/loupe.ts`. | No UIImageView magnification filter. |
| Value line | `show(_:_:fadeDelay:)` is `@label`, `@value` (null shows a dash) and `@fadeDelay`; the old value stays for the delay under a ghost copy, then crossfades. `isEnabled` is `@disabled`, and a missing value disables the native button. `isLit` is `@lit` with `aria-current`. `tint` returns a CSS colour. `.numbered` without wraps truncates instead of shrinking. | Args replace the method; CSS has no shrink to fit. |
| Big number | `field` and `unit` are `@value` (the text), `@unit`, `@onInput` and `@onEndEditing`. The arrow keys step too. The number is 32 px (`--canon-text-big-number`), the iOS 36 scaled like the other text styles. | Args replace the properties; keyboard access. |
| Fitting canvas | `.fitting` is `@fitting`: the band follows the content's own layout height through a ResizeObserver, so there is no `canvasFittingHeight` and no `refit`: every change refits. `@animated` eases a change at the same width over 0.3 s; a width change does not ease. Content with no height hides the band and its rules (`band(fitting:)`). The gallery's lines read Line 1 to Line 4. | Web layout knows the content's height. |

## Menus (shadcn gaps, no Swift source)

Web references are `~/GitRepos/delphitools` at `cb327df`. All five components place their panel with `lib/popover.ts`; Chrome 154 is the only browser they ran in.

| Component | Reference | Decision and deviations |
|---|---|---|
| Primitive | none | `lib/popover.ts` `attach(panel, anchor, { placement, invokes, gap, returnFocus })` gives the anchor a unique `anchor-name` (added to any it has) and the panel `position-anchor`, `position-area`, `position-try-fallbacks` and the gap margin, all inline; with `invokes` the anchor button becomes the panel's `popoverTargetElement` with `aria-controls` and `aria-expanded`. It pops the panel in and hands focus back to the anchor when the panel closes with focus inside. `placementStyle` is the pure table. An Ember modifier cannot apply another modifier, so the other four call `attach` and share `canon-popover.css` rather than render CanonPopover. |
| Platform | MDN BCD 8.1.3, caniuse | Popover API (Chrome 114, Safari 17, Firefox 125); anchor positioning `anchor-name`, `position-area`, `position-try-fallbacks` (Chrome 125 to 129, Safari 26, Firefox 147). No JS fallback. Names are explicit, so the changing initial value of `position-anchor` and implicit popover anchors do not matter. `position-area` uses the logical keywords (`block-end span-inline-end`). Not used: `popover="hint"` (Safari preview only), `interestfor` (Chrome only), `showPopover({ source })` (every opener is a button with `popovertarget`). Safari 26 and Firefox 147 unverified. |
| CanonPopover | `app/components/ui/popover.gts` (shadcn-ember 0.2.1) | One component with `<:trigger>` and `<:content>` blocks, both given `close`; the trigger block also gets `trigger`, a modifier for the consumer's `<button>`, chosen over an `@anchor` element because Ember has no element refs to pass. The panel is `popover="auto"` in the top layer, so no in-element to the body, and it stays inside a `<dialog>`. Light dismiss and Escape are the browser's; floating-ui `flip` and `shift` become `position-try-fallbacks`. `@placement` (12 values) replaces `side` and `align`; `sideOffset` is `--canon-popover-gap` (4 px). No `open`, `defaultOpen`, `onOpenChange`, `asChild` or PopoverAnchor. Opens with a 120 ms fade from scale 0.97 on the Web Animations API (`popover` in `lib/motion.ts`, from `dt-pop-in`); closes at once, as `hidePopover` cannot wait. Focus moves in only to an `autofocus` element, as in the reference. |
| CanonTooltip | `app/components/ui/tooltip.gts` | `popover="manual"`, `role="tooltip"`, its id added to the trigger's `aria-describedby`; the default block gets `trigger`, a modifier for any element. `@text` instead of a content component; default placement top. Shows on pointer enter (not touch) and on focus only when `:focus-visible`, so the focus after a click does not bring it back as it does in the reference. Hides on leave after 100 ms (`tooltipGraceMs`, the pointer may cross onto the tip), focus out, press and Escape. No arrow: anchor positioning does not report which fallback it took, so an arrow could point away from the trigger. No close animation. |
| CanonMenu | no dropdown in the web app; items, hint, check and rule from `app/components/substrata/layer-context-menu.gts` | Items are an `@items` data array (`CanonMenuEntry` in `lib/menu.ts`: item, checkbox, radio, separator; `icon`, `shortcut`, `disabled`, `destructive`, `items` for a submenu), not yielded components: type-ahead, the arrow keys, submenus and the menu bar need every title and state in one list, the pure parts (`wrap`, `typeAhead`, `menuRole`) port unchanged, and CanonPageStrip's menu already takes data. `@onSelect(item)`; the consumer flips `checked`. Keyboard as the APG menu button: click, Enter or Space open at the first item, Down and Up on the trigger at the first and last; Up and Down wrap, Home, End, type-ahead with a 500 ms buffer; the inline end arrow opens a submenu, the start arrow or Escape closes it; Tab or choosing closes, and focus returns to the trigger. Disabled items stay focusable with `aria-disabled` (APG), where macOS skips them. Submenus one level deep, a nested popover inside the parent panel, opened on hover without delay or pointer triangle. Rows 44 px at 15 px text where the reference has 32 px at 11 px; check and icon columns only when an item has one; separators are CanonRule. The panel is exported as `CanonMenuList` with `showMenu(panel, focus)`. |
| CanonContextMenu | `layer-context-menu.gts` and `app/lib/substrata/context-menu.ts` | A wrapper around its area (the root, `...attributes`) instead of a module store. Opens on `contextmenu` at the pointer, and on Shift+F10 or the context menu key below the focused element (the page strip's zero-position fallback kept). The anchor is a zero-size fixed span moved to the point, so the menu flips with `position-try-fallbacks`; the reference's `right-start` with 2 px offset becomes `bottom-start`, flush. Focus returns to the element focused when it opened. No target data in the callback: wrap each target in its own CanonContextMenu. No touch long press: iOS Safari fires no `contextmenu`. |
| CanonMenuBar | no reference, built from CanonMenuList, CanonGrid and CanonButton (cell) | `role="menubar"` on the root; one CanonGrid row of equal flush cells, each a CanonButton with `role="menuitem"`, `aria-haspopup` and the popovertarget of its menu; roving tabindex. Click toggles; Down, Enter and Space open at the first item, Up at the last; Left, Right, Home and End move between cells and carry an open menu along, focus left on the cell (APG recommended); the inline arrows past a menu's edge move to the neighbour's menu; the pointer over another cell switches while one is open, as in macOS; Tab out closes. The open cell is `--canon-accent-bg`. `@onSelect(item, menu)`. Cells are equal widths, where macOS sizes them to their titles. |
| CanonGrid | change | `place()` skips `[popover]` children, so a menu or popover rendered beside its trigger inside a grid is not counted as a cell. |
| Tokens | new | `--canon-popover-gap` 4 px, `--canon-popover-shadow` (the web app's `0 8px 28px rgb(0 0 0 / 25%)`, all three blocks), `--canon-menu-min-inline` 200 px, `--canon-tooltip-max-inline` 240 px. |

## Phases

A. Scaffold and foundation, one agent, sequential. Blocks everything else.
B. Five groups in parallel worktrees: controls, display, colour, colour-solid, math.
C. After the parallel session merges its Canon additions: port the new and changed files.
D. Merge, lint, test, gallery check in a browser.
